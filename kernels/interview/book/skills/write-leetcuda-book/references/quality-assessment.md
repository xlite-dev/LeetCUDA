  ch04/ch19/ch27（96）。

  ch17 97→95.5，其余基本不变。

## 4. 作为教学书籍的质量判断

**定位：源码级 CUDA/LLM kernel 专题教材（8.5–9/10）；零基础入门书 6/10；
工程参考手册接近 9/10。**

长处（有据）：

1. **公式与源码同构**：每条推导可回指源码行；ch02/04/05/10/12/15/19/27/34
   九条核心链经独立重推闭合。
2. **证据纪律**：性能数字标 GPU/形状/口径；ncu replay 时间不作 bench；
   独立 A/B 不可相加；README 与复测冲突标勘误（ch17 292T vs 183.8T）。
3. **把错误当教学内容**：ch08 `kNumWarps`、ch14 80 条 `setmaxnreg` 丢弃、
   ch16 Br=64/4warp 口径错配，都以考据框给出取证过程。
4. **可复现基础设施**：每章最小测试、218 条 PASS、可执行 bench、
   附录 B/C/D 的口径与构建矩阵。
5. **统一教学骨架**：导读（列问题）→ 数学 → 设计 → 图示 → 性能 → 考据 →
   坑 → 问答 → 测试，适合自学与面试准备。

短板（作为教材）：

1. **门槛陡且不均**：Part IV（ch20–26c）需先懂 CuTe；ch19b 白皮书放在 ch19
   之后，顺序应前置。无 CUDA/GEMM 基础者在 ch11/ch13 掉队。
2. **"注释即事实"残余风险**：多处叙述以源码注释为骨架，注释错时靠考据框纠偏，
   跳过考据框会被误导。
3. **性能数字难以复核**：PRO 5000/5090、单次短测、共享开发机；学生无法自证。
4. **少数归因仍是 MEDIUM**：ch17/18 arrive、ch26c STSM、ch27 254 码点、
   ch33 smooth-v。
5. **无习题体系**：只有"动手实验建议"，缺分级习题与参考答案，作课程教材需二次加工。
6. **协议章密度过高**：ch13/ch14/ch17 的 mbarrier/stage 协议缺"最小可跑中间态"缓冲。

## 6. 复核方式

书稿改动或新证据出现后：

1. 加载 `leetcuda-correctness-review`，按六维重审受影响章节；
2. 更新本文件对应行（分数、扣分点、日期），**不要另建新文件**；
3. 若某章分数变化 ≥2 分，在 `audit-history.md` 记一行原因；
4. 分数与扣分点冲突时，以台账（ledger / audit-history）为准。
